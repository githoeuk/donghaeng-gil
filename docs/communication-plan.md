# 동행길 통신 설계와 모의 공유

## 현재 범위

공식 마이현대·Kia App 연동을 목표로 하되 지원 여부는 미확인이다. 공개 SDK·API가 확인되기 전에는 인증 화면·중계 API를 가정하지 않는다. 현재 구현은 **한 Pleos 에뮬레이터 안에서만 실행되는 Debug 모의 시연**이다. 실제 두 기기 통신, 실차 주행, 공식 앱 연동 검증이 아니다.

## 구조

```text
기존 MainActivity ← PleosJourneySource / JourneyState (실제 내 차량 정보)

SharingDemoActivity → SharingTransport ← 향후 실제 통신 어댑터
                            ↑
                   MockSharingTransport (Debug만)
                            ↓
                SharingStore / SharingModels
```

화면은 SharingTransport의 Snapshot을 표시하고 그룹 참여·공유·메시지 명령을 호출한다. Debug의 연결 끊김·갱신 중단 버튼만 모의 시나리오 구현을 호출한다. 공식 연동 어댑터는 아직 만들지 않았다. Release에는 모의 Activity와 모의 통신 구현이 포함되지 않는다.

기존 내비 수집 코드는 모의 공유와 연결하지 않았다. 모의 화면을 열면 MainActivity의 수집이 중단되며 데모 차량은 모두 가상이다. 실제 송신 어댑터를 도입할 때 수집·공유 수명주기를 별도로 설계해야 한다.

## 데이터와 상태

- 그룹: 내부 그룹 식별자, 초대 코드, 참여·탈퇴 수명주기. 현재는 로컬 데모 그룹 `demo-group`과 코드 `DEMO42`만 사용한다. 실제 초대·인증 기능이 아니다.
- 차량 최신 상태: 참여자 식별자, 표시 이름, 좌표·주소, 목적지 식별자·이름·주소, 남은 초·미터, 순서 번호, 생성 시각, 로컬 단조 시계 수신 시각. 과거 이동 경로는 쌓지 않는다.
- 생성 시각은 송신 데이터의 시각, receivedAtElapsed는 수신 기기 내부 시각이며 기기 사이에 전송하지 않는다. 서버 수신 시각·시계 오차 보정은 실제 통신 구현에서 추가한다.
- 목록의 비교 기준은 모의 차량 가이며, 목적지 식별자가 다른 차량은 도착 순서 비교에서 제외한다. 내 실제 차량과의 ETA 비교를 의미하지 않는다.
- 메시지: 고유 ID, 발신자, 정해진 문구 종류, 전송 시각, 대기·전달·확인·실패 상태. 화면의 모든 전달·확인은 모의 결과라고 명시한다.
- 수신 상태는 단조 시계로 15초가 초과되면 오래된 정보로 판단하고 최신 ETA 표시를 보류한다. 연결 끊김에도 ETA를 확정해서 표시하지 않는다.
- 이전 순서 번호와 중복 메시지 ID는 거절한다. 확인 뒤 늦은 전달 이벤트로 상태를 낮추지 않는다.
- 그룹 전환·공유 중지·연결 끊김 후에는 이전 세대 콜백을 거절한다. 공유 중지는 차량 목록을 비우고 대기 메시지를 실패로 바꾼다. 그룹 탈퇴와 화면 종료는 메모리 상태를 지운다.
- 메시지는 최근 50개만 메모리에 둔다. 재연결 시 실패 메시지를 자동 재전송하거나 예전 위치를 업로드하지 않는다.

## 모의 시연 방법 (정차 상태)

1. Debug 앱 메인 화면의 **모의 공유 (정차 중)** 버튼을 연다.
2. **데모 그룹 만들기** 또는 `DEMO42`를 입력하고 **코드로 데모 참여**를 누른다.
3. **공유 시작**을 누르면 가상 차량 3대가 나타난다. 가·나는 데모 카페, 다는 다른 목적지인 데모 휴게소다. 약 5초마다 가상 값이 갱신된다.
4. 상황 메시지를 누른다. 약 2초 후 모의 전달, 4초 후 모의 확인과 상대의 가상 응답이 나타난다. **모의 응답 확인**으로 수신 확인을 표시한다.
5. **갱신 중단 시험** 후 15초 초과 시 오래된 정보 표시를 본다.
6. **연결 끊김 시험**과 **모의 재연결**을 시험한다. 재연결은 새 모의 상태를 만들며 실패 메시지를 재전송하지 않는다.
7. **공유 중지**와 **그룹 나가기**를 확인한다. 화면을 벗어나면 데모가 종료된다. 재진입·회전·프로세스 재시작 시 그룹은 복원하지 않는다.

데모 화면은 주행 중 사용을 위한 distractionOptimized 선언을 하지 않았다. 실차에서 주행 중 사용 가능한 UI라고 검증한 것은 아니다. 가상 데이터에는 실제 위치 센서·Pleos 목적지 정보를 사용하지 않고 외부 네트워크·디스크 저장도 하지 않는다.

## SDK 늦은 목적지 응답 방어

설치된 NaviHelper 3.0.5의 getDestinationInfo(), getRecentDestinationInfo()는 void이며 이벤트 콜백에는 애플리케이션이 전달한 요청 ID가 없다. 내부 AIDL의 문자열 인자만 보고 의미나 순서 보장을 추정하지 않는다.

목적지 변경·경로 시작 이벤트를 받으면 기존 리스너를 해제하고 SDK 연결을 새로 만든다. NavigationSession은 이전 리스너가 캡처한 연결 토큰을 거절한다. 취소·도착은 현재 세대의 목적지와 최근 주소 응답도 차단한다. 늦은 ROUTE_DRIVE 상태만으로 취소·도착을 되돌리지 않는다. 초기 idle 상태는 후속 정상 응답을 영구 차단하지 않으며, 목적지가 확인된 뒤 idle이면 경로 종료로 처리한다. 새 경로 시작·목적지 변경 또는 수동 다시 연결로 새 세대에 진입한다.

목적지 정보와 상세주소 캐시는 경로 변경·취소·도착·연결 해제 시 함께 초기화한다. 동일 목적지 내에서는 상세주소보다 빈약한 최근 목록 응답으로 주소를 낮추지 않으며 주소 수신으로 ETA 시각을 갱신하지 않는다.

**한계:** 이 토큰은 SDK 요청 ID가 아니라 리스너 수명이다. 서비스가 과거 요청 결과를 새 리스너에 재전달하거나 같은 리스너에 상태 이벤트 자체를 역순으로 전달하면 정확한 과거 여부를 판별할 수 없다. SDK 차원의 요청 연관성·순서 보장 또는 경로 식별 API 확인이 필요하다. 세대 번호로 모든 지연 응답을 완전히 식별했다고 주장하지 않는다.

## 실제 통신 전환 조건

1. 운영 측에 서드파티의 차량 내장 데이터망 사용 조건, 마이현대·Kia App 데이터 중계 SDK 제공 여부·권한·테스트 장비를 문의한다.
2. 공식 연결이 가능하면 SharingTransport 어댑터를 구현한다. 불가능하면 차량 직접 인터넷 중계 방식을 검토한다. 휴대폰 Bluetooth 중계는 별도 연결 API·실기기 검증이 필요하다.
3. 그룹 멤버 인증·읽기 권한·본인 정보만 쓰기, 초대 코드 추측 방지·만료·참여 승인, 탈퇴 후 구독 해제·접근 취소, 보관 기간·서버 삭제 정책을 실제 서비스에서 구현한다. 현재 데모는 접근 통제 검증이 아니다.
4. 실제 공유는 사용자 명시적 시작 뒤 최신 유효 상태만 전송한다. 목적지 취소·도착·공유 중지 상태도 명시적으로 전파한다. 위치·주소·목적지 모두 위치성 정보이며 실제 전송 전에 범위를 정한다.
5. 송신 세션 식별자와 순서 번호, 서버 시각, 중복 메시지 처리, 수신 확인 의미, 재연결 후 스냅샷 복구를 실제 어댑터에서 확정한다. 현재 단조 순서 번호는 동일 송신 수명 안의 모델이며 송신 기기 재시작까지 해결한 프로토콜이 아니다.
6. 두 에뮬레이터에서 실제 송수신·격리·끊김·재접속을 검증한 뒤 실차의 네트워크·주행 제한·백그라운드 동작을 별도로 검증한다. 한 에뮬레이터의 모의 성공을 실제 차량 간 통신 성공으로 설명하지 않는다.

```powershell
# JAVA_HOME/PATH가 없으면 -JdkHome '<설치된 JDK 경로>' 지정
& 'D:\projects\build-donghaeng.ps1' -Tasks @('assembleDebug','assembleRelease')
```
