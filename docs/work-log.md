### 한계와 미완료 항목

- SDK 공개 목적지 콜백에 요청 ID가 없다. 연결 토큰은 과거 리스너 응답을 차단하는 방어이지 개별 SDK 요청의 식별자가 아니다. SDK 서비스가 과거 결과를 새 리스너로 재전달하거나 상태 이벤트 자체를 역순으로 보내는 경우는 판별할 수 없다. SDK 보장 또는 추가 식별 수단 확인이 필요하다.
- 지연 콜백 순서는 순수 Java 세대·상태 검사로 재현했다. 실제 SDK에 임의 지연·역순 응답을 주입한 시험이나 실제 차량 주행 시험은 하지 않았다.
- 모의 그룹·초대 코드는 실제 인증·권한·다중 기기 연결이 아니다. 모의 전달·확인은 실제 상대 수신 증거가 아니다.
- 공식 앱 중계 API·차량 내장 데이터망 사용 범위·백그라운드 연결은 미확인이다.
- 공유 모델의 순서 번호는 동일 송신 수명 기준이다. 실제 연동에는 송신 세션 ID, 서버 수신 시각·시계 오차, 권한·초대 만료·접근 취소·데이터 삭제 정책이 추가로 필요하다.

## 2026-11-04 — 일반·제출 Release 분리와 모의 기능 소스셋 구성

### 구현

- `app/build.gradle`: distribution flavor로 standard/submission을 정의해 standardDebug·submissionDebug·standardRelease·submissionRelease 네 변형을 구성했다. applicationId·SDK 버전·기존 내비 기능은 유지했다. 두 Release는 debuggable=false다.
- 모의 포함 설정은 `BuildConfig.HAS_SHARING_DEMO`로 분리했다. Debug는 모두 모의를 포함하며, Release는 submission만 포함한다. DEBUG=true로 Release를 위장하지 않는다.
- `MockSharingTransport.java`, `SharingDemoActivity.java`를 src/debug에서 **src/demo**로 이동했다. 별도 demo 매니페스트의 Activity는 exported=false이며 DUMP 권한이 없다. src/debug 전체를 제출용에 포함하지 않아 SDK 진단·강제 경로 시험·기존 알림 시험과 NAVI_ROUTE_SEARCH 권한은 Release에서 제외된다.
- MainActivity에 명시적인 모의 안내를 추가했다. Debug에서만 안내를 확인하고 개발용 시연을 실행할 수 있다. 실제 정차 상태 SDK를 아직 연결하지 않았으므로 submissionRelease는 시연 안내에서 실행을 잠그며, Activity 자체도 같은 조건으로 모의 엔진을 시작하지 않는다. 이는 안전 기능 완료가 아니라 미확인 상태에서의 임시 차단이다.
- 모의 화면 재시작 시 메시지 렌더 캐시를 초기화해 종료·복귀 후 빈 메시지 상태가 올바르게 그려지게 했다.
- 서명 설정은 만들지 않았다. `verifyReleaseDistributionConfigured`는 의도적으로 Release APK/AAB 패키징을 차단한다. 후속 서명·안전 검증 단계에서 실제 준비 상태 검사로 교체해야 한다. unsigned나 Debug 서명으로 대체하는 옵션은 없다.
- `scripts/test-state.ps1`의 이동된 모의 소스 경로를 갱신하고 `scripts/verify-build-variants.ps1`에 변형별 컴파일·매니페스트·클래스·플래그 검사 56개를 추가했다.
- README, 통신 설계, 제출 가이드라인을 현재 구성·잠김 상태·검증 명령에 맞춰 갱신했다. 앞서 미커밋이던 가이드라인·작업 규칙은 보존했다. 저장소 밖의 로컬 빌드 스크립트는 수정하지 않았다.

### 검증

- 독립 Java 상태 검사 **91개 통과**.
- 네 변형 모두 Java 컴파일·리소스 처리·매니페스트 병합 성공. assembleRelease/package/bundle은 실행하지 않았다.
- 생성된 변형별 클래스·매니페스트·BuildConfig에 대한 **56개 구성 검사 통과**. standardRelease 모의 제외, submissionRelease 모의 포함, Release 진단 도구 제외, 동일 applicationId, Release 비디버깅, 비공개 모의 Activity, 새 INTERNET 권한 없음 확인.

- GPS는 에뮬레이터 시험 좌표를 사용했다. A 약 37.412720,127.094680, B 약 37.412798,127.094800. B를 37.412900,127.094898 및 37.412750,127.094700으로 변경하자 A에서 변경 좌표가 보였다. 앱에 원격 차량 예시 값을 주입한 시험이 아니다.
- 내비에는 Debug SDK 진단 경로(Donghaeng diagnostic destination, 37.4200/127.1000)를 요청했다. Pleos가 반환한 남은 시간 약 9~10분/1.8km를 실제 HTTP로 공유했다. 이 ETA는 에뮬레이터 내비 응답이며 실차 교통·주행 정확도를 검증한 결과가 아니다. 초기 검증에서 양쪽 ETA·같은 목적지 표시를 확인했다. 내비가 빈 목적지를 반환할 때는 상대에도 목적지 없음/ETA 확인 중이 표시됐다.
- 최종 Debug 빌드에서 A의 '휴게소 들를게요' → B 앱 수신 확인 → B 사용자 확인 → A '상대가 확인'을 확인했다. B의 '잠시 기다려 주세요'도 A 앱 수신 후 A 확인 → 양쪽 확인 상태로 바뀌었다. 화면 증거: .gradle/relay-a-ack.png, relay-emulator-5554-acknowledged.png, relay-emulator-5556-acknowledged.png.
- B가 화면을 벗어나자 그룹에서 B의 위치가 제거됐다. 서버 종료·재시작 후 기존 세션은 UNAUTHORIZED/연결 끊김이며 A는 확정 ETA 대신 최신 위치·ETA 확인 불가를 표시했다(.gradle/relay-a-offline.png). 서버 연결을 다시 누르면 그룹 미참여·공유 중지·이전 차량/메시지 없음으로 시작했다(.gradle/relay-a-reconnected.xml). 새 그룹·새 동의 없이 이전 공유를 복원하지 않았다.
- 실시간 화면 갱신 때문에 uiautomator가 idle 오류를 내는 경우가 있었다. 실패한 XML을 성공 증거로 사용하지 않고 최종 APK 스크린샷과 실제 버튼 조작으로 수신/확인을 판독했다. 동일 문구의 불필요한 setText도 줄였다.

### 범위와 후속 작업

실행·API·보관/인증 정책·온라인 이전 방법은 docs/local-relay.md, 제출 범위는 submission-release-guidelines.md와 README에 반영했다. 서버는 단일 프로세스 임시 인증 모델이며 온라인 서비스 운영·영구 계정·차량 소유 인증·휴대폰 공식 앱 중계·실차 데이터망/백그라운드 통신·실차 안전 심사·Release 런타임은 미검증이다. 실서비스 전 HTTPS 배포와 인증/참여 승인/삭제 정책을 확정해야 한다. Release 키·비밀번호·제출 APK/AAB는 생성하지 않았고 기존 artifacts 개발 APK를 교체하지 않았다. 커밋·푸시하지 않는다.

최종 빌드 재확인: 내비 경로를 새로 요청한 뒤 양쪽 모두 수정구 시흥동·동일 진단 목적지·약 9분/1.8km·같은 목적지가 표시됐다. 최종 증거는 .gradle/relay-emulator-5554-both-eta.png 및 relay-emulator-5556-both-eta.png다. B의 공유 중지 후 A에는 B의 공유 중지 상태만 남고 위치·ETA 행이 제거됐다(.gradle/relay-a-peer-stopped.png). 테스트 서버와 두 read-only 인스턴스를 종료해 임시 그룹·토큰·메시지를 제거했다. 원래 AVD 한 대(emulator-5554)를 일반 모드로 재시작하고 최종 Debug 설치·메인 진입을 확인했다. GPS는 시험 전 기본 좌표로 복원했다. 두 번째 인스턴스와 중계 서버는 종료된 상태다.

후속 사용자 요청으로 서버, 앱 연동, 문서의 세 작업으로 커밋을 나눴다. 688571a는 Node 메모리 중계·HTTP 통합 검사·Dockerfile, 793424f는 실제 앱 통신·공유 UI·네트워크 정책·송신 모델·검사 스크립트다. 문서 커밋에는 실행/온라인 이전 안내, 제출 범위와 이번 검증 기록을 포함한다. 서버 통합 검사와 diff 검사를 다시 통과했다. 코드 기능은 추가 수정하지 않았고 이전 빌드·에뮬레이터 검증 결과를 유지한다. 데이터는 H2나 파일 DB가 아닌 서버 프로세스 RAM의 Map에 임시 보관한다. 원격 푸시는 하지 않았다.

## 2026-11-04 — 내비 전환 후 위치·ETA 백그라운드 공유

사용자 요청: Pleos 백그라운드 실행 조건을 확인하고 내비 화면에서도 실제 공유를 유지한다. 이번 변경은 커밋·푸시하지 않는다.

### 플랫폼 확인과 결정

Pleos 공식 앱 구조/동작 모델은 화면 이탈과 앱 종료를 구분하며 통신처럼 지속해야 하는 작업의 실행·중단 정책과 리소스 절약을 설계하도록 안내한다. Android 공식 문서는 위치 공유를 location FGS 용도로 설명하며, 화면에서 사용자 동작으로 시작하고 위치 권한/설정·유형별 권한·지속 알림을 적용하도록 한다. Pleos FusedLocation 문서도 Android 백그라운드 위치 접근을 별도로 보장하지 않는다. 따라서 기존 LocationManager/NaviHelper를 유지하고 화면에서 시작한 location Foreground Service로만 지속한다. 무조건적인 상주·실차 승인·시동 종료 이후 실행을 확인한 것은 아니다. 출처와 조건은 docs/background-sharing.md에 링크했다.

### 구현

- SharingService가 실제 JourneyState/PleosJourneySource/HttpSharingTransport와 메모리 동의를 소유한다. Activity는 바인딩해 같은 세션을 표시하고 화면 이탈 때 UI 타이머·차량 조작 판별·바인딩만 정리한다. 공유 전 바인딩 단계에는 위치 수집이나 FGS를 시작하지 않는다.
- 공유 동의는 다른 앱에서도 위치·목적지·ETA를 전송하며 지속 알림에서 중지할 수 있음을 안내한다. Android13+ 알림 권한은 화면에서 요청하며 권한 허용 뒤에도 공유 시작을 다시 눌러야 한다. 위치/알림 설정·그룹 연결·정차를 재확인한다. foregroundServiceType=location, FOREGROUND_SERVICE/FOREGROUND_SERVICE_LOCATION을 모든 변형에 추가했다. Service는 exported=false다. ACCESS_BACKGROUND_LOCATION·부팅 수신기·절전 예외·WakeLock은 추가하지 않았다.
- 세대별 SharingLifetime이 중복·이전·지연·취소 후 시작을 거절한다. 서비스는 즉시 FGS 알림을 올린 다음 SDK 수집·서버 공유를 시작한다. 지속 알림 ID301/전용 채널은 무음·낮은 중요도로 위치/주소를 표시하지 않고 공유 중지 액션을 제공한다.
- 화면 밖에서는 서버 폴링을 약 1초에서 5초로 낮추고 위치·ETA 송신은 약 5초로 유지한다. 모의 데이터와 섞지 않으며 원본 신선도·위치 불일치·목적지 취소 방어는 유지한다. 백그라운드 메시지는 앱 수신만 확인하고 사용자 확인은 정차 UI에서 별도로 누른다.
- 중지/탈퇴/위치·알림 설정 해제 시 수집·업로드·알림을 종료한다. 화면이 없으면 연결도 닫아 그룹에서 빠진다. 시작 응답 10초/연결 오류 60초/동의 수명 2시간 한도를 둔다. START_NOT_STICKY/stopWithTask=true로 작업 종료·프로세스 재생성 뒤 자동 공유를 하지 않는다. 프로세스 강제 종료 시 탈퇴 요청 완료는 보장할 수 없어 서버 TTL을 사용한다.
- 화면 복귀 시 같은 서버·이름·그룹·공유 상태를 다시 표시한다. 종료된 서비스에 재진입했을 때 이전 차량/메시지가 남지 않도록 비운다. 실제 SDK reader의 설명을 수명 소유자 기준으로 수정했다. 기존 모의 화면의 이탈 시 종료 정책과 Release 패키징 차단은 유지한다.

### 자동 검증

### Pleos 에뮬레이터 검증

Pleos Connect v2.1.0, Android14/API34, emulator-5554/user10에서 실행했다. 로컬 Node 중계와 별도 HTTP 수신 클라이언트 BackgroundReceiver를 사용했다. 이번 검증의 수신자는 두 번째 Android 에뮬레이터가 아니라 실제 API를 호출하는 독립 클라이언트다. 이전 작업의 두 에뮬레이터 화면 공유 검증과 구분한다. 위치·차량·알림 권한을 허용한 상태로 실제 그룹을 만들고 명시적으로 공유를 시작했다.

1. 서비스 상태에서 isForeground=true, notification301, 유형 0x8(location), startRequested=true를 확인했다(.gradle/bg-service.txt). 공유 전 수신 위치는 null이었다.
2. 내비 앱으로 이동한 뒤 Group/Main/진단 Activity의 비표시·STOPPED 상태를 dumpsys로 확인했다(.gradle/bg-hidden-activities.txt). 멀티윈도우의 topResumedActivity 요약에는 이전 값이 남는 경우가 있어 해당 Activity의 실제 state·mVisible=false를 기준으로 확인했다. 앱 화면이 계속 보이는 분할 실행만으로 성공 처리하지 않았다.
3. 내비 화면에서 AVD GPS를 약 37.412720/127.094680 → 37.412798/127.094800 → 37.412900/127.094898로 변경하자 독립 수신자에게 새 좌표가 전달됐다. 내비에는 Debug 진단 목적지 37.4200/127.1000을 요청했고 Pleos SDK가 제공한 약 9~10분·1.8km를 실제 HTTP로 수신했다. 시험 좌표와 에뮬레이터 SDK ETA이며 실차 위치·교통 정확도 결과가 아니다.
4. 첫 세션 수신은 약 276초 동안 관측됐고 순서 번호 1→55가 진행됐다(중간 UI 복귀 포함). ETA가 유효한 수신 46건의 원본 나이 최대는 약 11초로 15초 신선도 기준 안이었다. 내비로 이동한 뒤에도 수 분 동안 새 위치·ETA가 이어졌다. 원본 로그는 .gradle/bg-peer-evidence.jsonl, 집계는 bg-summary.json, 화면은 bg-navigation.png다. 토큰은 수신 프로세스 메모리에만 두고 이 증거 파일에 기록하지 않았다.
5. 독립 수신자의 상황 메시지가 앱 수신(DELIVERED)으로 확인됐고, 화면 복귀 시 메시지 확인 버튼과 같은 초대 코드·차량 이름·공유 상태가 보였다(.gradle/bg-returned-group.png). 새 그룹·새 동의로 바뀌지 않았다. 알림 본문 탭의 화면 복귀 동작은 확정 검증하지 않았으며 앱의 일반 진입으로 복귀를 확인했다.
6. 내비로 다시 이동 후 Pleos 알림 센터의 '동행길 · 위치 공유 중'과 실제 '공유 중지' 액션을 확인·눌렀다(.gradle/bg-notification-panel.xml/png, bg-before-notification-stop.xml). 서비스가 (nothing)으로 사라지고 수신 데이터도 null이 됐다(.gradle/bg-stopped-service.txt). 화면이 없어도 사용자 중지가 동작했다.

- 첫 서버 종료는 콘솔 Ctrl+C 직후 에뮬레이터도 사라져 중단/재시작 연속 증거로 사용하지 않았다. 두 번째 실행은 서버를 Hidden 별도 프로세스로 띄우고 확인한 PID/명령행의 Node 프로세스만 Stop-Process로 종료했다. 앱 PID3913을 유지하면서 서버 연결 오류와 위치/목적지/ETA 제거를 확인했다(failure2-down-confirmed.xml/png). 첫 failure2-down 캡처는 타임아웃 감지 전이라 최신 약3초 데이터가 남아 있었고 최종 확인과 구분했다. 요청 타임아웃은 3초이며 즉시 통신 단절을 알아내는 기능이 아니다.
- 빈 일반 중계 서버를 같은 포트에 다시 띄우자 같은 앱 PID3913에서 세션 만료 안내·그룹 미참여·복사 비활성·공유 중지를 확인했다(failure2-restart.xml/png). 서버 연결을 명시적으로 누른 뒤 새 세션의 서버 연결됨·그룹 미참여·위치 공유 중지를 확인했다(failure2-reconnect.xml). UI 다섯 증거 파일의 오류/오래된 정보 누출/재연결 상태를 자동 대조해 통과했다.
- 일부 fresh 상태 uiautomator는 자주 바뀌는 데이터 때문에 idle 실패했고 해당 XML을 증거로 쓰지 않았다. 정상 데이터는 스크린샷, 오래된/실패/재시작은 성공한 새 XML로 판단했다. 활성 location FGS의 60초 연속 장애 종료, 짧은 네트워크만 끊겼다가 같은 서버에 복구되는 경우, 실차·온라인 HTTPS·서명된 Release는 이번 런타임 시험 대상이 아니었다.
- 로컬 fixture/합성 데이터/초대 코드 및 원본 캡처는 .gradle/failure-*·failure2-*에만 두며 Git 제외다. 토큰은 fixture 메모리에만 두었다. 마지막 앱 강제 종료·에뮬레이터 종료·확인한 중계 PID 종료로 정리했다. docs/local-relay.md에 실패별 동작을 추가했고 diff 검사를 통과했다. 커밋·푸시하지 않았다.
