# 메인 화면 위치·도착시간 연동

검증일: 2026-11-04 (한국 시간). Pleos Connect v2.1.0 / Android API 34 / 사용자 10. 에뮬레이터 시각과 호스트 시각은 다르다.

## 변경

- 기존 고정된 ‘Minsu, 12분’ 메인 화면을 실제 내 차량 정보로 교체했다.
- `PleosJourneySource`는 연결 후 5초 간격으로 현재 내비 위치와 목적지를 조회하고, 위치 콜백을 구독한다. 화면을 벗어나면 구독·리스너·연결을 해제한다.
- `JourneyState`는 GPS 위치 생성 시각과 내비 데이터 수신 시각을 구분한다. 15초를 넘긴 데이터는 최신으로 취급하지 않는다. 내비 위치의 수신 시각은 실제 측위 시각을 보증하지 않는다.
- 위치 불일치(300m와 GPS 오차의 2배 모두 초과), 낮은 정확도(100m 초과), 권한 없음·위치 비활성·위치 대기 상태에서는 ETA를 확인 필요 상태로 표시한다.
- 남은 시간이 0이라는 이유만으로 도착으로 판정하지 않는다. 명시적 도착 이벤트를 사용한다.
- 경로 취소 뒤 늦게 도착한 목적지 응답이 예전 ETA를 복원하지 못하도록 했다.
- 기존 알림 시험은 debug 전용 `NotificationDemoActivity`로 옮겼다. Release에는 실제 메인 화면과 NaviHelper 연동을 포함한다.

## 실제 확인한 결과

| 시험 | 결과 |
| --- | --- |
| 위치 권한 거부 | 앱이 종료되지 않고 ‘위치 권한이 필요합니다’ 표시 |
| 목적지 미설정 | ‘목적지를 설정해 주세요’ 표시 |
| 가상 경로 안내 후 메인 화면 | SDK가 보낸 목적지명, 약 8분, 1.8km, 도착 예정 시각 표시 |
| GPS 좌표 변경 | 메인 화면 좌표 갱신 및 ‘위치 확인 필요’ 전환 |
| 경로 취소 후 메인 재진입 | 목적지와 ETA 제거 확인 |
| Java 상태 테스트 | 25개 조건 통과 |
| Debug·Release 빌드 | 성공 |

가상 시험 목적지명은 `Donghaeng diagnostic destination`이다. 이 문자열과 ETA는 진단 Activity가 요청한 내비 경로 결과에서 받았으며 메인 화면의 고정 표시값이 아니다. 경로 취소 시 Pleos 내비 화면이 앞으로 이동하여, 취소 후 동행길로 돌아와 표시 해제를 확인했다.

위치 시험은 `adb emu geo fix`로 가상 좌표를 주입한 것이며 실제 차량·실제 GPS 주행 시험이 아니다. 시험 후 경로 취소를 확인하고 초기 에뮬레이터 GPS 좌표를 복원했다. 메인 화면은 데이터를 표시하기만 하며 다른 차량에 전송하지 않는다.

## 재현

1. Debug APK를 Pleos 에뮬레이터 사용자에 설치한다.
2. 위치 권한을 거부한 상태에서 메인 화면의 권한 안내를 확인한다.
3. 정확한 위치를 허용하고, GPS를 내비 기준 좌표에 맞춘다.
4. 기존 SDK 진단 Activity의 `probeRoute=true`로 가상 경로를 요청한다. 경로 시작 콜백을 받은 뒤 MainActivity를 연다.
5. 메인 화면에서 SDK 목적지·남은 시간·도착 시각을 확인한다.
6. GPS를 다른 가상 좌표로 바꾸고 위치 확인 상태로 전환되는지 확인한다.
7. 진단 화면의 자동 취소 후 메인 화면으로 돌아와 목적지·ETA가 제거됐는지 확인한다.

SDK 진단 Activity의 명령과 권한은 [기존 검증 문서](pleos-location-eta-verification.md)를 참고한다. 테스트 XML·스크린샷·로그는 로컬 `.gradle/main-screen-test/`에 보관했다.

## 주소 중심 표시

- 현재 위치의 위도·경도 표시를 Pleos `CurrentLocationInfo.address`로 교체했다.
- 목적지는 장소명 아래에 `DestinationInfo.address`를 표시한다. 주소가 비어 있으면 ‘주소 정보가 없습니다’를 표시한다.
- GPS와 내비 좌표가 50m 이내이고 양쪽 데이터가 15초 이내일 때만 그 주소를 현재 위치로 사용한다.
- 주소가 없거나 위치가 맞지 않으면 ‘주소 확인 대기’와 설명을 표시하며 raw 좌표로 대체하지 않는다.
- GPS 이동 뒤 이전 주소 숨김, 오래된 주소·권한 없음 처리, 목적지 취소 뒤 주소 초기화를 포함해 25개 상태 조건을 검증한다.
- 외부 주소 조회와 새 INTERNET 권한은 추가하지 않았다. 주소의 상세 수준은 Pleos 제공값을 따른다.
- 주소 화면 시험: 현재 위치와 목적지에 수정구 시흥동 표시, 원시 좌표 제거, GPS 불일치 시 이전 주소 숨김을 에뮬레이터에서 확인했다. 스크린샷과 UI XML은 .gradle/address-screen-test/에 보관했다.
## 실제 매장 목적지 검증 (2026-11-04)

Pleos 내비에서 `Starbucks`를 직접 검색하고 실제 검색 결과 `스타벅스 분당궁내DT점`을 선택해 추천 경로 안내를 시작했다. 임의 이름을 붙인 진단용 목적지는 사용하지 않았다.

| 항목 | 확인 결과 |
| --- | --- |
| 내비 매장 상세주소 | 경기도 성남시 분당구 대왕판교로 302 |
| 내비 추천 경로 | 12분, 5.6km |
| 동행길 가게명 | 스타벅스 분당궁내DT점 |
| 동행길 SDK 주소 | 분당구 궁내동 |
| 동행길 도착 정보 | 약 12분, 16:41 도착 예정, 5.6km 남음 |

가게명과 남은 시간·거리는 내비 결과와 일치했다. 도착 예정 시각은 SDK 남은 시간을 기기 시각에 더한 표시다. SDK 주소는 매장 상세 화면의 도로명 주소와 달리 동 단위로 전달되므로 상세주소 표시까지 검증된 것은 아니다. 현재 앱은 이 값을 그대로 표시한다.

시험은 에뮬레이터에서 수행했고 GPS 입력을 내비의 가상 현재 위치에 맞췄다. 실제 차량 주행 검증은 아니다. 화면 증거는 로컬 `.gradle/shop-main.png`에 있다. 경로는 사용자가 확인할 수 있도록 선택 상태로 남겼다.

## 상세주소 보완 및 실측 결과 (2026-11-04)

`getRecentDestinationInfo()` 응답에는 현재 안내 중인 매장의 도로명 상세주소가 포함됨을 확인했다. 현재 목적지와 POI ID, 하위 ID, 제공자, 이름이 모두 같고 좌표 차이가 100m 이내인 항목만 사용한다. 최근 목적지의 주소가 더 길고 번지 숫자를 포함할 때 보완하며, 일치하지 않거나 조회 실패·주소 없음이면 기존 SDK 주소를 유지한다. 100m 허용은 매장 중심과 진입점 좌표 차이를 수용하기 위한 값이다. 별도 외부 API·위치 전송·네트워크 권한을 추가하지 않았다.

목적지 변경 시 캐시를 초기화하고, 응답이 늦게 와도 현재 목적지에 다시 매칭한다. 취소·도착 후에는 주소를 복원하지 않으며, 주소 응답으로 ETA의 수신 시각을 갱신하지 않는다. 최근 목적지 목록은 앱 메모리에서만 처리하고 로그·파일·서버에 저장하지 않는다.

수정 APK를 에뮬레이터에 설치해 기존에 직접 검색한 `스타벅스 분당궁내DT점` 경로로 재확인했다. 화면에 `경기도 성남시 분당구 대왕판교로 302`가 잘림 없이 표시됐으며 `약 12분`, `5.6km`도 유지됐다. 스크린샷·UI 구조는 로컬 `.gradle/shop-detail.png`, `.gradle/shop-detail.xml`에 있다. 실제 주행 검증은 아니며 매장 이름·주소를 코드에 하드코딩하지 않았다.

검증: 상태 처리 25개 + 주소 매칭 11개 테스트 통과, Debug·Release 빌드 성공. 다른 POI·하위 ID·제공자·매장명·먼 좌표·잘못된 좌표·누락 주소를 거부하고 원래 주소를 유지하는 조건을 확인했다.

## 후속 변경: 내비 연결 세대 및 Debug 모의 공유

목적지 변경·경로 시작 시 SDK 리스너를 새로 생성해 이전 리스너 응답을 버리고, 취소·도착 후에는 같은 연결의 목적지·상세주소 응답도 차단한다. 초기 idle과 경로 확인 후 idle을 구분하며 종료 상태를 늦은 ROUTE_DRIVE로 해제하지 않는다. 이 방식은 SDK 요청 ID 식별이 아니므로 서비스 내부의 새 연결 대상 과거 응답까지 구분한다고 보장하지 않는다. 상세 내용은 [통신 설계](communication-plan.md)를 참고한다.

Debug의 모의 공유는 내비와 분리된 별도 화면이며 실제 내 차량 정보를 사용하지 않는다. 메인 화면 복귀 시 기존 스타벅스 분당궁내DT점·도로명주소·ETA·거리 표시를 에뮬레이터에서 재확인했다. 실제 차량 간 통신 시험은 아니다.
