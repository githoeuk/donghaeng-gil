# 실제 로컬 중계 / 온라인 이전

2026-11-04. SharingTransport의 HttpSharingTransport가 실제 HTTP API를 사용한다. MockSharingTransport는 기존 모의 화면에만 남는다. 공식 마이현대·Kia App API를 사용하거나 지원을 확인한 구현은 아니다.

## 실행

Node.js 22 이상(검증: D:\node.exe 24.18.0), 외부 패키지 설치 불필요.

```powershell
cd D:\projects\donghaeng-gil
& D:\node.exe relay/server.mjs
# 다른 터미널에서
& D:\node.exe --test relay/server.test.mjs
```

기본 127.0.0.1:8787에서만 수신한다. 에뮬레이터 두 대에서 같은 Debug APK를 실행하고 정차(P, 속도 0, UX 제한 없음)를 확인한다. 처음 부팅한 Pleos에서는 내비 앱을 한 번 실행해 초기화하고 양쪽에서 경로 안내를 시작한다. 메인 → 동행 그룹 → 차량 이름 입력 → 서버 연결. A가 그룹을 만들고 표시된 초대 코드를 B가 입력해 참여 요청을 보낸 뒤 A가 승인한다. 각자 위치 공유 동의 후 공유 시작을 누른다. 주소는 Pleos와 GPS가 일치할 때, ETA는 유효한 내비 안내·정확한 최신 GPS 조건에서만 전송한다. 내비 목적지가 없으면 ETA를 만들지 않는다.

Debug 기본 URL은 http://10.0.2.2:8787 (Android 에뮬레이터의 호스트 별칭). Debug 평문 통신도 10.0.2.2/127.0.0.1/localhost 세 호스트만 허용한다. 실제 장비 LAN HTTP 주소를 허용하지 않는다. Release는 HTTPS만 허용하며 서버 주소를 직접 지정한다. 서버 주소·인증 토큰은 저장하지 않는다.

명시적인 동의 후 location Foreground Service로 SDK 수집·최신 위치 송신 약 5초를 유지한다. 화면 수신은 약 1초, 다른 앱 사용 중에는 약 5초다. 지속 알림의 공유 중지로 종료할 수 있고 화면 복귀 시 같은 그룹에 연결한다. 수명주기·권한·종료 정책은 [백그라운드 공유](background-sharing.md)를 따른다. 정차 중에만 그룹 설정·공유 시작·메시지 조작을 허용한다. 주행/상태 미확인 중 메시지를 숨기고 이미 시작한 공유는 내비 등 다른 앱에서도 유지한다. 공유 중지·탈퇴는 항상 가능하다. 안전 승인 완료를 의미하지 않는다.

## 프로토콜 accessVersion 2 (/v1 경로 유지)

모든 변경 요청은 JSON, 세션 발급 외에는 Authorization: Bearer 토큰. 토큰·차량 이름·위치·메시지 본문을 서버 로그에 남기지 않는다.

| 요청 | 용도 |
| --- | --- |
| GET /health | 개인정보 없는 상태 확인 |
| POST /v1/sessions | 차량 이름으로 임시 토큰·차량 ID 발급 |
| POST /v1/groups | 초대 그룹 생성 |
| POST /v1/groups/join | 초대 코드로 승인 대기 요청 |
| POST /v1/groups/invite/rotate, /revoke | 그룹장 코드 재발급/폐기 |
| POST /v1/groups/requests/approve, /reject | 그룹장 참여 승인/거절 |
| POST /v1/groups/kick | 그룹장 강제 퇴장 |
| GET /v1/group | 현재 본인 그룹 스냅샷 |
| POST /v1/sharing | enabled로 공유 시작/중지, 시작마다 새 epoch |
| PUT /v1/state | epoch·증가 sequence·최신 위치/목적지/ETA 또는 available:false |
| POST /v1/messages | UUID·REST/WAIT/GO/OK, 중복 ID 재생성 방지 |
| POST /v1/messages/{id}/received | 상대 앱이 실제 수신했다는 확인 |
| POST /v1/messages/{id}/ack | 상대 사용자의 명시적 확인 |
| POST /v1/groups/leave | 탈퇴 및 본인 위치 제거 |

클라이언트는 본인 세션의 상태만 쓸 수 있고 그룹 밖 메시지에 확인할 수 없다. 공유 중지/재시작 후 이전 epoch의 업로드는 거절한다. 15초 초과 원본은 업로드하지 않는다. 수신 때 원본 나이·오프라인·요청 지연을 반영해 오래된 ETA를 숨긴다. 전달됨은 상대 앱 수신 확인, 확인됨은 사용자 버튼이다. 여러 구성원에서는 1명 이상이 수신/확인했다는 의미이며 전원 확인이 아니다. 네트워크 오류 시 메시지 자동 재발송이나 이동 이력 큐를 만들지 않는다. 서버 재시작 후 재연결·새 그룹·새 동의가 필요하다.

## 저장·운영 경계

단일 프로세스 RAM만 사용한다. 세션 최대 100개/2시간, 그룹 최대 50개/8대, 초대 코드 40비트·발급 후 30분 만료, 그룹 빈 경우 삭제. 15초 무응답은 오프라인, 60초 무응답은 탈퇴·위치 삭제, 상태 보관 최대 60초, 메시지 최대 50건/30분. 그룹장이 나가거나 서버 종료 시 그룹 데이터가 없어진다. 응답 본문·요청 크기 제한, 요청/초대 시도 제한이 있다. 계정 인증·차량 소유 증명은 없다. 생성자가 그룹장이며 코드 재발급/폐기·참여 승인/거절·강제 퇴장을 지원한다. 그룹장 탈퇴/연결 만료 시 그룹 전체를 종료한다. 세부 기준은 [그룹 접근 권한](group-access-control.md)을 따른다.

## 온라인 배포 준비

서버 코드는 HOST/PORT 환경변수를 받고 relay/Dockerfile을 제공한다. 다음은 향후 배포 예시이며 이번에는 Docker 빌드나 외부 배포를 하지 않았다.

```powershell
docker build -t donghaeng-relay ./relay
docker run --rm -p 127.0.0.1:8787:8787 donghaeng-relay
```

HTTPS 도메인의 역방향 프록시가 이 포트로 전달하게 구성하고 앱의 서버 URL을 해당 HTTPS 루트 주소로 변경한다. 인증 헤더·위치 본문 로깅을 꺼야 한다. 프록시 연결·요청 제한, 인증서 갱신, 서비스 모니터링을 적용한다. Node 포트를 직접 인터넷에 열지 않는다. 현재 메모리 모델은 인스턴스 1개만 지원하며 수평 확장·영구 로그인·장기 보관은 구현하지 않았다. 실서비스 전 계정/차량 인증·현재 그룹 권한의 운영 기준·개인정보 처리/보관 정책을 확정하고 필요하면 저장소를 교체한다. 클라이언트 모델과 SharingTransport 경계는 그대로 유지할 수 있다.

자료: [에뮬레이터 네트워크](https://developer.android.com/studio/run/emulator-networking), [Android 네트워크 보안 설정](https://developer.android.com/privacy-and-security/security-config), [Node HTTP](https://nodejs.org/api/http.html).

## 두 차량이 같은 그룹에 참여하는 순서

초대 코드를 앱이 상대에게 자동 전송하지는 않는다. 차량 A가 만든 코드를 상대에게 직접 알려주고 차량 B에서 입력한다. 정차가 확인된 상태에서만 코드 복사와 설정을 조작할 수 있다.

1. 개발 PC에서 위 실행 명령으로 중계 서버를 켠다.
2. 두 에뮬레이터에서 동행길 → 동행 그룹을 연다. 둘 다 같은 서버 주소 http://10.0.2.2:8787을 사용하고 서로 구분되는 차량 이름을 입력해 서버 연결을 누른다.
3. 차량 A에서 그룹 만들기를 누른다. 그룹장이 표시된 초대 코드를 읽거나 초대 코드 복사를 눌러 직접 전달한다. 복사는 해당 Android 기기 클립보드에만 저장하며 PC·휴대폰·다른 에뮬레이터로 자동 전달하지 않는다. Android 13 이상은 민감한 클립으로 표시한다.
4. 차량 B에서는 새 그룹을 만들지 않고, A에게 받은 코드를 초대 코드 입력란에 입력해 참여 요청을 누른다. 그룹장이 승인하기 전에는 차량 정보가 보이지 않는다. 코드는 그룹 생성 후 30분이 지나면 신규 참여에 사용할 수 없다.
5. 그룹장이 관리 화면에서 참여 승인 또는 거절을 선택한다. 승인 후 양쪽 모두 같은 그룹 구성원이 보이는지 확인한다. 그룹 참여만으로 위치 전송이 시작되지 않는다.
6. 각 차량에서 공유 시작을 누르고 전송 범위에 동의한다. 위치 권한·알림 권한·정차 조건을 확인한다.
7. 상대 차량의 주소·목적지·ETA를 확인한다. 내비 안내가 없거나 위치가 오래되면 ETA는 확인 중/갱신 지연으로 표시될 수 있다. 기본 내비의 배경 지도 미표시 문제는 별도 조사 중이다.
8. 종료할 때 공유 중지 또는 그룹 나가기를 누른다. 두 차량을 모두 종료한 뒤 PC 중계 서버도 종료하면 메모리 데이터가 사라진다.

서버 연결 전, 그룹 미참여, 그룹 참여 후 안내가 화면 상태에 맞춰 바뀐다. 초대 코드 복사는 유효 코드가 있는 그룹장이며 연결·정차가 확인된 경우에만 가능하다. 그룹장은 재발급/폐기를 할 수 있으며 이전 코드와 대기 요청은 무효화된다. 일반 구성원은 코드를 받지 않는다.

## 연결 실패·세션 소실·코드 만료 안내

- 네트워크 요청 실패 시 상대 위치·목적지·ETA·메시지 스냅샷을 화면에서 제거한다. 같은 서버 프로세스에 일시적으로 다시 연결되면 새 응답으로 복구하며 메시지는 자동 재전송하지 않는다.
- 정상 응답이라도 원본 나이가 15초를 넘는 차량은 주소·좌표·목적지·ETA를 모두 숨기고 갱신 지연을 표시한다. 서버의 최대 보관 시간(60초)과 화면의 최신 정보 유효 시간(15초)은 다르다.
- 서버 재시작/세션 만료의 UNAUTHORIZED 응답은 그룹·공유 의도·수신 데이터를 지우고 이전 세션의 자동 폴링을 멈춘다. 정차 후 서버 연결을 다시 누르고 그룹 생성/참여와 공유 동의를 새로 해야 한다.
- 잘못됐거나 만료된 초대 코드는 한국어 안내를 유지하며 서버 연결 자체를 끊긴 것으로 표시하지 않는다. 새 코드 참여 등 다음 요청이 성공하면 안내를 지운다.
- 코드의 만료는 신규 참여만 막는다. 만료 전부터 연결된 구성원의 그룹을 만료만으로 종료하지 않는다. 서버가 재시작하면 기존 코드는 더 이상 유효하지 않다.
